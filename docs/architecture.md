# AgentNode 架构

管理对话是入口，Core 是执行能力；HTTP 不是业务所有者。详见 [AdminAgent](admin-agent.md)。

```text
crates/agent-node/src/
  main.rs / lib.rs   进程入口 / 导出门面
  app/              启动配置、装配、关闭
  cli/              终端对话、导航、确认
  http/             Web 资源、SSE、鉴权、对话适配
  management/       AdminAgent、管理 Skill、宏注册管理 Tool
  core/             状态、业务 Agent、会话、策略、权限
  a2a/              注册、挂载、下行 RPC、机器协议
  storage/          JSON 文件与版本化策略存储
  tests/            跨模块集成测试
```

mod.rs/lib.rs 只声明模块和导出；运行时状态由对象封装。旧顶层处理器、表单和配置脚本不作为第二套管理架构保留。
目前 prelude.rs 集中现有模块的依赖导入；Core 和 A2A 仍在一个 crate，不宣称已经物理拆成完全独立库。

## 信任边界

每个节点有独立 Node ID、文件目录和管理口令。一次性邀请换 AK/SK，子节点主动连父节点。下行 RPC 带路径、项目、访问链与待处理请求 ID，回复必须匹配子节点身份。
上游挂载授权覆盖当前项目整个后代子树；传统 local_agents 仅限定传统会话任务路由。挂载是信任授权，不是端到端加密隧道。
ADMIN_TOKEN 是节点级管理员身份，不是多租户 RBAC；项目隔离保证会话/策略/工具上下文分离。多用户使用独立进程与目录。

## 数据与并发

state.json 普通 JSON 原子快照；OS 锁阻止同目录多实例，写入失败不更新内存。注册邀请码消费与凭据保存原子提交。
管理会话和业务会话历史独立，打断保留部分输出，重启标记未完成任务而不自动重放工具。
群策略版本检查在同一文件事务内完成。跨节点冻结不是全球事务；远程取消和断线自动重试仍有限制。
整文件快照适合个人和小规模环境，海量事件需另行分片/压缩，而不是假设能无限增长。
